# phoenix-ash-tenant — Shen-Backpressure for Elixir + Ash

The multi-tenant authorization chain from
[`examples/multi-tenant-api`](../multi-tenant-api/) ported to Elixir.
It uses plain Mix plus Ash with the ETS data layer, so there is no
Phoenix and no database. One Shen spec
([`specs/core.shen`](specs/core.shen)) drives:

```
verified-token → authenticated-user ─┐
operator-credential ─────────────────┴→ authenticated-principal (sum)
    → tenant-access → resource-access → write-access
```

| Artifact | Generated by | What it enforces |
|---|---|---|
| `lib/tenant/shen/guards_gen.ex` | `sb gen` (shengen-ex) | One `@opaque` struct per datatype; `new/N` checks every premise and returns `{:error, {:premise, "<shen premise>", values}}` |
| `shen/guard_tracer.ex` | `sb gen` | Compile tracer (wired in `mix.exs`): `%Guard{}` literals, struct updates and `struct/2` next to guard types fail `mix compile` |
| `lib/tenant/shen/policy_gen.ex` | `sb gen` (`[elixir] ash_out`) | Ash `SimpleCheck`/`FilterCheck` per access rule: the actor must *be* the proof struct, issued for the request tenant |
| `test/derived/*_spec_test.exs` | `sb derive` (shengen-ex derive) | ExUnit + StreamData: `Tenant.Authz` ≡ the Shen `define`, evaluated in-process by shen-erl |
| `.sb/mutation_report.json` | `sb mutate-spec` | Every `: verified` premise has a hostile witness in `specs/hostile/` |

## Run it

```bash
# once: build shen-erl (https://github.com/pyrex41/shen-erl) next to this repo
make ci          # sb gates (7 gates) + Dialyzer
make demo        # tracer, shen-derive and mutate-spec each catch a planted bug
```

`SHEN_ERL_ROOT` defaults to a `shen-erl` checkout next to the repository.
Set it if yours lives elsewhere.

`sb gates` runs these gates, in order:

| Gate | Command | Catches |
|---|---|---|
| shengen | `sb gen` | stale guards |
| build | `mix compile --warnings-as-errors` | forged guard structs (tracer), type/arity drift |
| test | `mix test` | chain + hostile cases, Ash policies, tracer, derive |
| shen-check | `bin/shen-check.sh` | spec (and `specs/good/`) no longer typechecks under `(tc +)` in shen-erl |
| tcb-audit | `sb audit` | generated files drifted, hand-written code in the guard namespace, raw `__struct__` maps in `lib/`, tracer not wired |
| shen-derive | `sb derive` | derive tests drifted from the spec, or the impl disagrees with the Shen oracle |
| mutate-spec | `sb mutate-spec` | a premise no hostile program depends on |

## The hostile cases

| Attempt | Elixir | Shen (`specs/hostile/`) |
|---|---|---|
| empty token signature | `VerifiedToken.new/2` → `{:premise, "(not (= Sig \"\"))", …}` | `01_empty_signature.shen` rejected |
| alice's token + bob's user id | `AuthenticatedUser.new/2` → `(= User (head Token))` | `02_mismatched_user.shen` |
| operator without secret | `OperatorCredential.new/2` | `03_empty_operator_secret.shen` |
| non-member tenant access | `TenantAccess.new/3` → `(= IsMember true)` | `04_non_member.shen` |
| document from another tenant | `ResourceAccess.new/3` → `(= Owner (head (tail Access)))` | `05_cross_tenant.shen` |
| unknown role | `Role.new/1` → `element?` | `06_unknown_role.shen` |
| viewer writes | `WriteAccess.new/2` → `(can-write? Role)` | `07_viewer_writes.shen` |
| `%TenantAccess{…}` literal / `struct/2` | `mix compile` fails (tracer) | n/a |
| proof for tenant B used on tenant A | Ash `Forbidden` (`TenantAccessCheck`) | n/a |
| plain map posing as a proof | Ash `Forbidden` | n/a |

`sb mutate-spec` drops each premise in turn and checks that its hostile
file starts typechecking. All 7 premises are killed, each by exactly the
file written for it. [`specs/good/`](specs/good/) is the positive
control. Those guarded constructions must keep typechecking, which needs
the `verified-if` rule in [`specs/verified.shen`](specs/verified.shen).

## Notes

- The principal variants use single-line (`___`) rules. The double-line
  form adds left rules, and those drive shen-erl past its inference
  budget when a principal is pattern-bound.
- A pattern match on a guard struct outside its module (`%HumanPrincipal{}`)
  breaks `@opaque`, and Dialyzer reports `call_without_opaque`.
  `Tenant.Authz` uses `is_struct/2` instead.
- `Tenant.Authn` (HMAC check) and `Tenant.Directory` (membership) are the
  TCB for the I/O-backed premises. See [AUDIT.md](AUDIT.md).
